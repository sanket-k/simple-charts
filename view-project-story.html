Project 101

A stranger should reach “I understand this system” in ten minutes. Start here.

The pitch

Simple Charts answers one question: how do I turn raw spreadsheet data into a branded, publication-quality chart sized for social media — without installing anything, signing up, or writing code?

It is a single-page, browser-only studio: paste CSV/TSV/JSON or type rows, pick from 19 chart types, style it, drop in a logo, and export a PNG/JPG/WebP/SVG at exactly 1200×675 (Twitter/X), 1080×1080 (Instagram), 1200×627 (LinkedIn) or 1200×900 (general). No backend, no accounts, no telemetry; the only network requests are five pinned CDN libraries at page load (README.md:35, index.html:55, README “Export & Sharing”).

The moat is the method, not the data. Generic tools ship line/bar/pie. This app ships the charts analysts actually argue with: an Innovator’s Dilemma disruption curve (541 lines of formula-driven geometry, src/charts/innovator.js), a Kano feature-prioritization model (402 lines), a segmented-bar editor with multi-group support, dumbbell / bubble-compare / overlay comparisons on shared log-axis helpers, a dual-bar target-vs-current chart, and an inflation purchasing-power calculator. Stack: vanilla ES2020+ modules, Chart.js 4.5.1, PapaParse 5.5.3, plain CSS — zero build step (CLAUDE.md; .agent/rules/rules.md:7-15).

Who built it and how: Sanket, solo, 2026-04-16 → 2026-06-29 (70 commits), working AI-assisted. No Co-Authored-By trailers exist, so attribution is artifact-based: Kilo Code planning files predate the repo (2026-03-20, stash@{0} .kilo/plans/) and a committed AI-rules doc governs the codebase (87e9e6a); three worktree-agent-* branches mark Claude Code sessions. The core mechanism

Data pipeline (the machine every chart runs through)

Input → parseInputText() → rawParsedData → applyDownsampling() → parsedData → applyZoom() → validateChartData() → builder → chartInstance

One parse pipeline feeds all 19 charts. The registry (src/charts/registry.js:1) is the single source of truth: each chart module registers a descriptor (id, label, icon, builder, isSelfManaged, capabilities) at import time, and render.js dispatches with one lookup instead of a 17-branch switch (todo.md “Success Metrics”: 17 → 1).

Worked example: the inflation formula

equivalent = amount × (1 + r) ^ (target − base)

Configured values from the shipped sample: amount $1,000, rate 3%, base year 2026, target year 2036 → 1000 × 1.0310 = $1,343.92 (“what today’s money is worth then”). Reverse the years (target 2016) and the same formula returns 1000 × 1.03−10 = $744.09 (“what it was worth previously”) — both directions are supported (todo.md §8.2).

The prototype playground with 8 live variants lives at inflation/; the integrated “Value-Track” chart is src/charts/inflation.js registered as id: 'inflation'.

Thresholds & bands (constants.js:44-52)

  • ≤500 rows → pass through untouched (data.js:23)
  • ≤2,000 rows → monthly downsample (data.js:24)
  • >10,000 rows → warning toast (warnRowLimit)
  • >50,000 rows → hard stop (hardRowLimit)
  • 30 bars max; 12 pie / 10 donut slices max
  • 300ms render debounce (debounceMs)

Missing-data behavior & guarantees

  • Empty or non-numeric data → validateChartData() returns a specific human message per chart (“No valid numeric data found. <chart> requires numbers in the value columns.”) and render is blocked with a toast (render.js:66-72)
  • Self-managed charts (innovator, kano, timeline, dual-bar, inflation) generate their own data when the textarea is empty — validation only runs when parsed data exists (render.js:40-48)
  • Guarantees: nothing leaves the browser; same input + same settings = same pixels; no server-side truth to drift

Blocker post-mortems

Six moments the project stalled, what actually broke, the fix as shipped, and the transferable lesson.

1 · Exports silently lost custom drawings 1d659bc

Broke: dumbbell connectors, bubble-compare arrows, ratio pills — anything drawn by chart-specific inline plugins — vanished from exported PNGs.

Why: doExport() built its config by replacing the entire plugins array, dropping the chart’s inline plugins (todo.md §4.1 records the root cause).

Fix: clone the config but preserve inline plugins, replacing only the shared ones.

Lesson: config cloning must be identity-preserving for chart-specific extensions — any “fresh options object” shortcut eats plugin data.

2 · The debounce race, fixed twice be14bfc 88f65e8 dfc2798

Broke: color/zoom controls re-rendered synchronously (Apr 19-20); a month later segmented group updates still did (May 4).

Why: the render trigger is a judgment call at every call site — there was no single policy.

Fix: window.__debouncedRender() became the convention; rules.md:85 now mandates it.

Lesson: a bug fixed twice in two weeks is a missing convention, not two bugs.

3 · Radar chart clamped at 100 ad7bac1

Broke: radar data above 100 rendered wrong; the axis refused to auto-scale.

Why: suggestedMax: 100 hardcoded in the shared options.

Fix: replaced with beginAtZero: true (2026-05-12).

Lesson: magic numbers in shared options silently clamp user data — defaults must derive from the data, not the developer’s sample.

4 · Validation gate blocked self-managed charts render.js:40-48

Broke: innovator/kano/timeline — charts that generate their own data — hit “No data to render” because validation ran with an empty textarea.

Why: the registry applied one validation path to two chart lifecycles.

Fix: validate only when state.parsedData exists; self-managed charts skip the gate.

Lesson: a gate needs lifecycle awareness. Post-script: the fix is demonstrably in the code, yet todo.md §5.1 remains unchecked — the plan and the code disagree (see Data room).

5 · The node_modules mirage 5b8164b 3f8c9a8

Broke: nothing user-facing — but two commits titled “add Zod v4 and Kilocode SDK dependencies to project node_modules” and “update kilo dependencies and sync zod v3/v4 modules” contain only app.js / index.html / styles.css diffs. No node_modules, package.json, or lockfile was ever tracked.

Why: an experiment (a toolchain layer) was abandoned within hours; the commit titles were written for work that never landed.

Fix: the experiment was dropped; its residue (.vite/deps/) is still tracked.

Lesson: commit messages are documentation. In an AI-assisted fleet, the tool writing the title may not be the tool writing the diff — verify.

6 · The 6,814-line first breath 036d040

Broke: nothing — but the “initial commit” is a squash: a 1,208-line app.js, full styles, markup, and a 4,375-line cryptocurrency CSV in one shot, dated 2026-04-16.

Why: scratch work was collapsed into a clean entry point; a Kilo plan dated 2026-03-20 proves the missing weeks.

Fix: the CSV was deleted eight days later (08fea6a, “clean up: removed unused file”).

Lesson: the repo starts at chapter two of this story — size your expectations of “day one” accordingly.

Lessons

What this repository teaches — each one pinned to evidence, not opinion.

1 · The highest-leverage refactor is the one you can measure

The registry rewrite “cost” three feature-less days and returned 39→0 .includes, 17→1 dispatch branches, 6→2 files per new chart — numbers the team wrote down (todo.md Success Metrics). Measure refactors or nobody believes them.

2 · Build-then-split works — if you split within a week

The monolith lived six days and 4,417 lines. Any longer and the split tax compounds; any sooner and you abstract the wrong seams. Day-6 is the sweet spot this repo hit (c025719).

3 · A stash is not a backup

The product’s entire written strategy (4,814 lines), a test suite, a license, and a .gitignore all live in three stashes — one git stash drop or a re-cloned machine from oblivion. Anything you would mourn belongs on a branch.

4 · Commit messages that describe work that never landed are worse than none

The node_modules mirage (5b8164b, 3f8c9a8) sends every future archaeologist hunting for dependencies that were never committed. In AI-assisted work, verify the diff against the title.

5 · If UI truth lives in the DOM, persistence gets expensive

~116 settings inputs are read at render time from the form, not from state. That choice made the UI fast to build — and made save/search (the current feature request) a form-serialization project instead of a state-dump. Feature-request/save-search-request.md is the receipt.

6 · A bug fixed twice is a missing convention

Debounce races were patched Apr 19-20 and again May 4. The durable fix was not the patch but the rule (rules.md:85): one debounced bridge, mandated.

7 · Docs rot faster than code

Within eleven weeks, CLAUDE.md was wrong about the dispatch mechanism, the dependency versions, the DOM-ref count, and its own file tree — while the code it describes stayed correct. Docs need the same review trigger as code.

8 · Zero tests is a decision — even an unmade one

The abandoned suite in stash@{2} proves the intent existed. At 12,844 LOC with 19 chart types, every export bug (1d659bc) and axis bug (ad7bac1) was found by eye. The panel scores this the repo’s deepest debt.

9 · Formula charts need their own lifecycle, not an exception

Innovator/Kano/Timeline broke the data-driven assumption until isSelfManaged made the difference structural (render.js:40-48). Model your variants in the type system, not in conditionals.

10 · Velocity decays unless the queue is real

3.2 commits/day for 19 days, then −89%. What kept the tail alive was a written queue (todo.md phases, then the feature-request doc). The repo stops exactly where the queue stops — at the save/search fork.
